✳ practest.live · app.practest.live

UI/UX report: the public site and the web app

A full read of both web products as they stand in source on 12 August 2026 — design tokens, every page and route, the role model, the admin console, navigation, and where the two diverge from each other and from the Android client.

Method

Read from source: web/ (Astro static site) and app/ (React + Vite SPA). Colours, sizes, breakpoints and routes are quoted, not estimated. Nothing here was checked in a live browser, so rendering bugs that only appear at runtime would not show up — but the layout facts below are structural and hold regardless.

01 The public site

practest.live — “the examination paper, reimagined”

Astro, statically exported, near-zero client JS. Eight pages, one layout, one stylesheet. The identity is committed and unusually specific for a product site.

Ruled paper

A fixed repeating-linear-gradient on body::before draws a 48 px ruled line across every page at 14 % opacity. Costs nothing, and it is the single device that makes the site feel like stationery rather than SaaS.

OMR bubbles

13 px circles, some filled with the accent, one with the saffron marker. Used in the hero proof line and the footer. A brand mark drawn in CSS, not an image.

Marker-pen underline

.marker-underline lays a skewed saffron highlight behind one word per headline — “real exam hall”, “educators”. Restrained: one word, once per page.

Chrome — header, footer, floating actions

Sticky glass header

1200 px container. Brand lockup (32 px gradient tile + saffron “e-Learning” mono eyebrow + “Practest®”), three nav links, a 38 px circular theme toggle that rotates 12° on hover, then Login (secondary) and Start free (primary) pointing at the SPA.

Footer

Four columns — Prepare, Exams, Company, Registered Office with a real address and phone — over a dashed rule carrying the parent-company line, PAN, GSTIN and ISO certification. Column headings are saffron mono at 0.75 rem.

Two floating action buttons

WhatsApp (#25d366) and Call, pinned bottom-right, 54 px pills that collapse to 50 px circles under 600 px. The WhatsApp button carries a 2.6 s pulsing ring, suppressed under reduced motion.

Theme boot

An inline script reads the practest_theme cookie (scoped to .practest.live), falls back to localStorage, then to dark — before first paint, so there is no flash. Toggling writes the cookie back, which is how the site and the app stay in sync across subdomains.

The header navigation disappears on phones with nothing to replace it

At max-width: 760px the stylesheet sets .navbar-links { display:none } and .nav-login { display:none }. There is no hamburger, no drawer, no <details> fallback. On a phone the header is reduced to the logo, the theme toggle and Start free — Courses, About, Contact and Login are all unreachable from the top of the page. The footer still carries them, so navigation technically survives, but only by scrolling to the very bottom of a long marketing page. For an audience that is overwhelmingly mobile, this is the most costly defect on the site.

The numbers on the landing page are hardcoded, and the testimonials are invented

“690+ Exam Mocks”, “15,000+ Aspirants”, “15k+ Active Students”, “98.4% Exam Accuracy”, “120+ Mocks”, “45 Mocks”, “31 Exams” — all literal strings in index.astro, none derived from the database. The three quotes attributed to “Ananya S.”, “Rohit K.” and “Meera D.” sit under a section the source itself comments as ASPIRANT VOICES (placeholder). Two of the four “product facts” are honest claims about the engine; the audience-size figures are not. This is live, indexed, and running as ad landing copy — decide deliberately whether to source these from real counts or remove them.

What the site does properly

  • Canonical URLs, per-page title/description, Open Graph and Twitter cards, Organization and FAQPage schema.
  • theme-color declared per colour scheme — the browser chrome matches the page in both themes.
  • Analytics gated behind a consent banner; nothing loads until the cookie is set.
  • Scroll reveals via IntersectionObserver with a no-JS fallback that just shows everything, and a prefers-reduced-motion block that disables them outright.
  • Visible focus rings, semantic <details> for the FAQ, real <address> markup.
02 The web app

Super-admin is a superset, not a separate console

Both admin roles land on the same /admin/dashboard; super-admins additionally see a “👑 Platform Governance” group in the sidebar with White-Label Settings, Admin Accounts & Onboarding, and System Audit Logs. The consequence is that SuperAdminGuard and SuperAdminDashboard.jsx are now dead — the guard is defined and never used, the dashboard imported and never rendered.

The student surface

Persistent header

A sticky glass bar at top:12px shown only to students: brand lockup linking home, a STUDENT chip, the user's name, and Logout. Admins get no such bar — their identity lives in the sidebar footer instead.

Unverified-phone banner

A non-blocking amber strip under the header whenever phone_verified is false, with a Verify Phone Now button. Correct choice — it nags without gating, which matters because OTP delivery is still pending a DLT template.

Dashboard

2 rem “Student Dashboard” heading, then two prominent buttons — Request Activation / Redeem Code and Results History — then activation-request status, enrolled course cards, an optional purchase section, and the test list for the selected course. Note the contrast with Android, where the same two destinations are bare icons.

Test series

Reached at /student/test-series — a real URL, but with no link to it from the dashboard body or the header. Today it is effectively reachable only by typing the address or following an assignment link.

The CBT engine — a desktop layout

The exam screen is a fixed two-column workspace: a calc(100vh - 100px) container with overflow: hidden, a glass sub-header carrying the test title, the active section chip and one or two header-clock readouts in JetBrains Mono with tabular figures, then a flexible question pane beside a fixed 320 px palette rail.

The rail holds the section selector — with locked sections greyed to 40 % opacity and a “Locked” pill — above a five-across grid of teardrop palette buttons (border-radius: 50% 50% 0 50%, the same shape SSC and IBPS render), and a legend of five 16 px squares. Options are .mcq-option rows that shift 3 px right on hover and take a gradient badge plus a double ring when selected.

The admin console

A 280 px solid sidebar beside a scrolling main pane. Eight core panels for every admin, three more for super-admins. Panel choice is React state, not a route.

📚 Courses & Syllabus 📝 Question Bank 🏆 Tests Manager 🎯 Test Series Builder 👥 Batches & Enrollments ⏳ Activation Requests 🔑 Activation Codes 📊 Results Dashboard 🎨 White-Label Settings 🚀 Admin Accounts & Onboarding 📋 System Audit Logs

One genuinely good touch: a global CSV-import status bar that polls every 2 s and stays visible across panel switches, colour-coded pending / success / partial-failure with a “View Details” jump. Background work that reports itself is rarer than it should be.

The app has no responsive design at all

There is exactly one @media query in the entire SPA, and it is prefers-reduced-motion. Every layout is inline styles; what adaptivity exists comes from auto-fit / minmax grids and flexWrap, which rescues card lists but cannot rescue fixed widths. Two places break hard on a phone:

  • The admin sidebar is width:280px; flexShrink:0. On a 360 px screen it consumes 78 % of the viewport and cannot be collapsed.
  • The CBT screen puts a fixed 320 px palette rail next to the question pane inside an overflow:hidden box. At 360 px the question area is left with roughly 20 px. The exam is unusable on a phone.

That last point matters more than it looks: the site's own FAQ tells students “the palette and timer stay fully usable on a phone.” The marketing copy and the code disagree, and the copy is the one students will act on.

A one-word bug on a screen every admin must pass through

Admin2FASetup.jsx line 51 sets flexDirection: 'col'. That is not a valid CSS value — React writes it, the browser discards it, and the container falls back to row. The mandatory 2FA enrolment card therefore lays its heading, QR block and form out horizontally inside a 500 px box. 'column' is the fix.

Smaller things worth knowing

  • Eleven admin panels share one URL. No deep links, no browser back between panels, and a refresh always returns to Courses. Sharing “look at this result” with a colleague is impossible.
  • Two icon systems. The app ships a 25-glyph inline SVG Icon component, but the admin sidebar uses emoji — which render as full-colour, differently on every OS, and ignore the theme.
  • Razorpay's checkout.js loads on every route, including the login page, regardless of whether the payment gateway is switched on. It is a third-party script on 100 % of page views for a feature that is off by default.
  • Modals are fixed multi-column grids. The Tests Manager editor is 1.2fr 1fr 1fr at 90 vh; the Question editor 1fr 1fr. Neither reflows.
  • Loading states are considered — a shared .spinner, a shimmering .skeleton, and role-specific copy: “LOADING PRACTEST”, “LOADING PRACTEST ADMIN”, “LOADING SUPER ADMIN CONSOLE”.
  • Panels stagger in. .glass-panel animates rise-in over 0.5 s, with 50 ms delays applied to the 2nd–6th sibling so a grid assembles rather than snapping.

Night is genuinely one product

Ground, panel, border, ink, accent and gradients match to the hex across all three. A student crossing from the site to the app in dark mode sees one continuous surface.

Day is three-quarters of one product

The site's warm ivory is a deliberate, good choice — it is the exam-paper idea. But nothing carries it across the subdomain: click Login and the ground turns cool blue and the accent shifts indigo. Either carry the ivory into the app's day theme, or accept the break and make it feel intentional at the boundary.

The theme follows the student

Both webs read and write practest_theme on .practest.live before first paint, so the choice persists across subdomains with no flash. Android is the exception — its preference is local to the device and does not participate.

Typography is where Android falls behind

Both webs load the same three families from Google Fonts. The Flutter app bundles none and renders in Roboto, which is why it reads as a plainer product than the site that shares its palette exactly.
