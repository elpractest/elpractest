e-Learning Practest · Android (Flutter)

UI/UX report: every screen, token and route

A complete read of the student Android client as it stands in source on 12 August 2026 — launch sequence and its timings, the full screen inventory, both colour themes token by token, the type scale, the component library, and the navigation graph.

How this was produced, and what it does not prove

Everything below is read from the Dart source and is exact — colours, sizes, durations and routes are quoted from the files, not estimated. It is not a visual sign-off: screenshots on the emulator come back as a black frame regardless of renderer, so no screen in this report has been reviewed with human eyes on a device. Treat it as a specification of what the code will draw, and budget a real device pass before release.

01 · Launch

The launch sequence, to the millisecond

Three distinct things happen before a student sees anything they can tap. Two of them are ours; the first belongs to Android.

Android system splash

Drawn by the OS from LaunchTheme until Flutter's first frame. Shows the launcher icon centred on the window background — white in light mode, dark in values-night. Duration is not ours to set; it is however long the engine takes to start.

Flutter splash 2600 ms

splash_screen.dart. One AnimationController drives every element through Intervals, so the whole sequence stays in lockstep and retiming is a single edit.

Handoff 420 ms

An AnimatedSwitcher cross-fades to the intro or the dashboard. The aurora backdrop is shared by both, so only the content changes — it reads as one continuous screen, not a cut.

Mark size is device-aware

132 dp on phones, 190 dp when the window's shortest side is ≥ 600 dp. The halo box is 1.9× the mark; the ring is 1.52×.

Reduced motion is honoured

If the platform's “remove animations” setting is on, the whole sequence collapses to 900 ms and the halo does not loop. The brand still appears — it just doesn't move.

The splash is not a loading screen, deliberately

Session.init() — token restore and the /me call — finishes in main() before runApp, so the auth state is already known when the splash starts. The splash is gated on nothing and awaits nothing, which means it cannot become a place the app hangs. The cost is that a returning student watches 2.6 s of animation before their dashboard; if that proves too long in use, the single constant _full is the only thing to change.

Two structural weaknesses worth naming

  • Test series and results are hidden behind unlabelled icons. They are two of the product's strongest features and neither has a label, a tab, or a card on the dashboard — only a 24 dp glyph in the header. A student who does not tap them will never find the study path.
  • There is no persistent navigation. Every route below the dashboard is a push, so returning always means walking back. No bottom bar, no drawer, no home affordance from three levels deep.

04 · Colour

Two complete themes

Ported one-to-one from the web SPA's index.css. Every colour in the app resolves through useColors(context), which reads the active brightness — there are no hard-coded colours in the screens except the CBT statuses below.

The toggle was inverted until this week

MaterialApp's theme slot is the light one and darkTheme the dark one; the two palettes were crossed, so “dark mode” resolved to the light palette and the sun/moon toggle did the opposite of what it promised. Because the controller defaults to dark, a fresh install opened light. Now fixed — which also means every screen renders differently from how it did before, and none has been reviewed in the dark palette it was designed for.

06 · Components

The shared library

Fourteen widgets in widgets.dart and scaffold.dart do almost all the work. Radii are fixed at three steps: 10 (small), 14 (medium), 20 (large).

GlassPanel

The card everything sits in. 20 px radius by default, 1 px border, translucent panel fill, and a single deep shadow — 0 20px 50px −12px rgba(2,6,18,.5). Optionally tappable, which several cards use instead of a button.

GradientButton

Primary action. Primary gradient, 10 px radius, 24×13 padding, 15 px semibold label, and an accent-coloured glow — 0 8px 22px −6px — that is dropped entirely when disabled. Swaps its label for an 18 px spinner while loading.

SecondaryButton

Bordered, filled with the faintest surface tint, same radius and metrics. Drops to 40 % fill opacity when disabled.

AppHeader

The frosted bar on every signed-in screen: 34 px gradient tile with a mortarboard glyph, the eyebrow + wordmark lockup, an optional trailing slot, the user's name truncated at 110 px, and a Logout chip. Sub-screens reuse it with the name slot repurposed as a page title and logout hidden — economical, but it means the header lies about what that text is.

StatusChip · MedallionIcon · ProgressBar

A pill with optional icon tinted by semantic colour; a rounded-square icon badge at 18 px radius with a 12 % tint fill; and a rounded progress bar, 10 px tall by default and 12 px in the course header.

MathText

The most specialised piece. Splits $$…$$ block and $…$ inline maths, and additionally sniffs undelimited LaTeX so question banks that forget the delimiters still render. Six of the seven unit tests in the project cover this.

AuroraBackground

The app's signature: three blurred radial orbs — indigo top-right, purple beside it, cyan bottom-left — each drifting (0,0) → (−24,+20) px and breathing 1.00 → 1.12 scale over a 26-second reversing loop. It renders on every screen including the test engine, and it never stops. Two consequences: it is a permanent, if small, background GPU cost, and it makes pumpAndSettle unusable in widget tests because the tree never reaches a settled state.

08 · Assessment

What is strong, and what I would fix

Holds up well

  • The test engine. Fixed top and bottom bars with a scrolling question body is the right shape for a timed exam — the clock and the primary action never move.
  • The CBT palette is theme-locked. Someone thought carefully about the one place where a colour changing meaning would actually cost a student marks.
  • Tabular figures on the countdown. A small detail that stops the timer twitching every second.
  • Empty states are written, not defaulted. “When your institute assigns a test series to your batch, it will appear here” explains the system, rather than saying “no data”.
  • One token system, no stray colours. Every screen resolves through useColors.

Would fix, in this order

  1. Surface test series and results properly. Two unlabelled header icons are hiding the study path and every past score. A bottom navigation bar with Home / Series / Results is the obvious answer.
  2. Bundle the brand fonts. Roboto everywhere is why the app looks less considered than the website that shares its palette.
  3. Stop overloading AppHeader's name slot as a page title. Give it a real title property.
  4. “View Tests” is a hidden mode switch. Tapping it appends a section far below the fold with no scroll and no visible change near the button — it looks like nothing happened.
  5. Consider pausing the aurora during a test. Ambient motion behind a timed exam is a small but constant distraction, and a free battery saving.

Still unverified before release

  • No screen has been seen on a real device or emulator — captures return black.
  • The tablet two-column intro has never been rendered; the only AVD available is a phone.
  • Nothing has been exercised against the production API — the machine's VPN egress is blocked by the host's bot protection.
  • The dark palette is newly correct as of this week, so every screen's dark rendering is effectively brand new and unreviewed.
